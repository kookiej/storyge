# Storyge

등록해 둔 인스타그램 계정들의 **스토리를 확인 → 썸네일 보고 고르기 → 로컬에 저장**까지 해 주는 프로그램입니다.

스토리는 24시간이 지나면 사라지므로, 필요한 것만 골라 정해진 이름 규칙으로 모아 두는 것이 목적입니다.

**쓰는 방법이 두 가지 있습니다.** 둘은 같은 `data` 폴더와 저장 폴더를 쓰므로 계정 목록이 공유됩니다.

| | exe (창) | 웹 (브라우저) |
|---|---|---|
| 실행 | `Storyge.exe` 더블클릭 | `python -m storyge serve` |
| 인스타 로그인 | **필요합니다** | **필요 없습니다** (있으면 더 잘 됩니다) |
| 비공개 계정 | 팔로우 중이면 가능 | 세션이 있으면 가능, 없으면 불가 |
| 예약 수집 | 있음 | 없음 |
| 파일명 | `YYMMDD @계정 #번호` 고정 | 원본 이름이 기본, 직접 조합 가능 |
| 올라온 시각 | 정확 | 세션이 있으면 정확, 없으면 받은 시각 |

로그인하기 싫거나 계정 위험을 피하고 싶으면 웹, 비공개 계정까지 받아야 하거나 창을 닫아 두고
자동으로 모으고 싶으면 exe 를 쓰면 됩니다.

# exe 로 쓰기

exe 는 **두 개**입니다. 원하는 폴더에 두고 더블클릭하세요. 파이썬이 없는 PC에서도 동작하고,
검은 콘솔 창은 뜨지 않습니다.

| 파일 | 화면 |
|---|---|
| `dist\Storyge.exe` | 인스타그램 앱의 디자인 언어를 참고한 화면. 오른쪽 위에서 **한국어/영어**와 **다크/라이트** 전환 |
| `dist\Storyge_demo.exe` | 처음 만든 기본 화면. 한국어 고정이고 모양을 바꿀 수 없습니다 |

**기능은 완전히 같고 보이는 모습만 다릅니다.** 둘 다 exe 옆의 같은 `data` 폴더를 쓰므로
계정 목록·즐겨찾기·로그인 세션·저장 기록이 공유됩니다. 한쪽에서 계정을 추가하면 다른 쪽에도 보입니다.

> 디자인은 색·여백·스토리 링 같은 **표현 방식을 참고**한 것입니다.
> 인스타그램의 로고·워드마크·아이콘 자산은 쓰지 않았고, 앱 이름도 `igstory` 그대로입니다.

창 하나에서 전부 처리합니다.

```
┌─ 저장 폴더 ─────────────────────────────────────────┐
│ D:\스토리                              [폴더 선택]  │
├─ 계정 ──────────────────────────────────────────────┤
│ ★ @abc                     [즐겨찾기 켜기/끄기]     │
│   @def                     [선택 삭제]              │
│ ★ @ghi                     (여러 개 선택 가능)      │
│                                                     │
│ 추가 [abc def ghi        ] □즐겨찾기로    [추가]    │
├─────────────────────────────────────────────────────┤
│ ○전체 계정  ○즐겨찾기만  [스토리 가져오기] [다시 로그인] │
├─ 진행 상황 ─────────────────────────────────────────┤
│ 새 스토리 7개를 찾았습니다.                          │
│ 저장: 260830 @abc #1.jpg                            │
└─────────────────────────────────────────────────────┘
```

처음 쓸 때는 **저장 폴더를 정하고 → 계정을 추가**한 뒤, `스토리 가져오기` 를 누르세요.

- 계정 추가는 `abc def ghi` 처럼 띄어쓰기로 **여러 개를 한 번에** 넣을 수 있습니다.
- 계정 ID는 `@abc`, `abc`, `https://www.instagram.com/abc/` 중 아무 형태나 됩니다.
- 추가할 때 옆의 **★** 을 켜면 즐겨찾기로 등록됩니다.

**목록 다루기**

- 여러 개를 골라 한 번에 삭제하거나 즐겨찾기를 바꿀 수 있습니다.
  고른 뒤 **`Del` 키**를 눌러도 지워집니다.
- **전체 선택 / 전체 해제** 버튼으로 한 번에 고르고 풀 수 있습니다.
- 이미 고른 항목을 **더블클릭하면 선택이 풀립니다.**
- **삭제 전 확인** 을 꺼 두면 지울 때 묻지 않습니다. (기본은 물어봄)

**가져올 범위**는 셋 중에 고릅니다 — **전체 계정 / 즐겨찾기만 / 선택한 계정만**.

**오른쪽 위**에서 **한국어 ↔ 영어**(`KR`/`EN` 글자를 누르면 바뀝니다)와
**다크 ↔ 라이트**(스위치)를 바꿉니다. 둘 다 기억되며, 바꾸면 창을 다시 그립니다.

## 예약 수집

`예약` 버튼(`스토리 가져오기` 옆)에서 설정합니다. **앱을 닫아 두어도** 지정한 시각에
윈도우 작업 스케줄러가 대신 실행해 스토리를 모아 둡니다.
예약은 **여러 개** 만들 수 있습니다 (예: 즐겨찾기는 3시간마다, 나머지는 매일 밤 한 번).

1. `새 예약` 을 눌러 실행 방식을 고릅니다. `이번만` 을 고르면 시각 하나만 정하면 되고,
   `반복` 을 고르면 아래 네 가지 중에서 고릅니다.

   | 반복 | 입력 | 예 |
   | --- | --- | --- |
   | 매일 | 시각 | `9:30` — 매일 아침 9시 30분 |
   | 일마다 | 간격(일) + 시각 | `3` + `21:00` — 사흘마다 밤 9시 |
   | 시간마다 | 간격(시간) | `6` — 6시간마다 |
   | 사용자 지정 | 간격(시:분) | `1:30` — 1시간 30분마다 |

   시각과 간격은 앞자리 `0` 을 붙이지 않아도 됩니다 (`9:30` = `09:30`).

   > `이번만` 예약은 정한 시각에 한 번 실행한 뒤 **스스로 꺼집니다.** 목록에는 `꺼짐` 으로
   > 남으니, 다시 켜면 그대로 또 쓸 수 있습니다. 그 시각이 오늘 이미 지났으면 내일 실행합니다.
2. 대상 계정을 직접 적거나 `목록에서 가져오기` / `즐겨찾기만 가져오기` 로 채웁니다.
   비워 두면 등록된 계정 전체를 봅니다.
3. 목록에서 예약을 골라 `수정` · `켜기/끄기` · `삭제` 할 수 있습니다.
   각 줄에 반복 방식 · 대상 계정 · **다음 실행 시각** · 마지막 실행 결과가 함께 보입니다.
4. 모인 스토리는 `data\staging\` 에 임시로 쌓이고, 다음에 앱을 열면
   **`예약 (12)`** 처럼 버튼에 개수가 붙습니다.
5. 버튼을 눌러 `저장하기` 를 누르면 평소와 같은 선택 창이 뜹니다.
   고른 것만 저장 폴더로 옮겨지고, 나머지는 보관 기간까지 남습니다.

보관 기간은 기본 **7일**이며 창에서 바꿀 수 있습니다. `비우기` 로 즉시 지울 수도 있는데,
누르면 **전체** 를 지울지 **직접 선택** 해서 지울지 물어봅니다. 직접 선택을 고르면 평소와 같은
썸네일 창이 떠서 지울 것만 고르면 됩니다.

예약 창 아래쪽에서 지금 무엇이 돌고 있는지 볼 수 있고, 예약 수집이 실행 중이면 `중지` 로
멈출 수 있습니다(다음 계정으로 넘어가기 전에 멈춥니다). `기록 지우기` 는 실행 기록과
진행 상태를 함께 지웁니다(예약별 `마지막 실행` 표시도 사라집니다).

`실행 상태` 와 `마지막 실행` 은 **예약으로 돈 것만** 보여 줍니다. 창에서 직접 누른
`스토리 가져오기` 는 여기 섞이지 않습니다.

`최근 실행 기록` 에는 **받은 스토리 개수**와 **문제**(로그인 실패·요청 제한·비공개 계정 등)만
남습니다. 잘 돌아간 날은 한 줄이면 충분하고, 뭔가 잘못됐을 때만 내용이 늘어납니다.

> 시각과 간격은 **시 칸과 분 칸이 따로** 있고 사이의 `:` 는 고정입니다. 숫자만 들어가며,
> 시 칸을 두 자리로 채우면 분 칸으로 저절로 넘어갑니다.

> **알아 두실 점**
> - 예약 실행은 **잠금 화면에서도** 동작하고, **절전 상태면 PC를 깨워서** 실행합니다.
> - 다만 **완전히 끄거나 최대 절전 상태면 깨우지 못합니다.** 또 윈도우 전원 옵션에서
>   '절전 모드 해제 타이머 허용'이 꺼져 있으면 깨우기가 동작하지 않습니다.
> - 놓친 실행은 다음에 PC를 켤 때 따라잡지만, **스토리는 24시간이면 사라지므로
>   그 사이 만료된 것은 받을 수 없습니다.**
> - 예약 실행은 저장된 로그인 정보를 씁니다. **2단계 인증이나 본인 확인이 필요해지면
>   창을 띄울 수 없어 그냥 건너뜁니다.** 무슨 일이 있었는지는 `data\schedule.log` 에 남습니다.

`스토리 가져오기` 를 누르면 새 스토리를 찾아 **선택 창**이 뜹니다. 저장할 항목을 클릭해 고르고
`저장` 을 누르면 내려받습니다. `취소` 를 누르면 아무 파일도 만들지 않습니다.

범위에서 **`직접 입력`** 을 고르고 `스토리 가져오기` 를 누르면, 작은 창이 떠서 계정을 적을 수
있습니다. 한 번만 확인하고 싶은 계정에 쓰세요 — **계정 목록에 등록되지 않습니다.**

선택 창의 `더 가져오기` 를 누르면 계정을 골라 **그 자리에서 더 찾아** 목록에 덧붙일 수 있습니다.
이미 고른 항목은 그대로 남습니다. 새로 나온 것만 추가되고, 이미 저장한 스토리는 나오지 않습니다.

> 두 곳 모두 같은 창을 씁니다. 위 목록에서 계정을 고르면 아래 입력칸에 자동으로 채워지고,
> 직접 적어 넣어도 됩니다. **입력칸에 보이는 것이 곧 가져올 계정**입니다.
>
> 목록은 계정 목록과 똑같이 다룹니다 — **끌어서** 여러 개를 고르거나, Ctrl·Shift 로 골라잡거나,
> `전체 선택` 으로 한꺼번에 넣을 수 있습니다. 고른 항목을 더블클릭하면 선택이 풀립니다.
> 선택을 풀어도 입력칸에서는 지워지지 않으니, 필요 없는 계정은 입력칸에서 지우면 됩니다.

선택 창은 **최소화**할 수 있습니다. 고르는 도중에 잠깐 다른 일을 보고 작업 표시줄에서 다시
부르면 됩니다.

가져오는 동안에는 `일시정지` 와 `취소` 버튼이 나타납니다.

- `일시정지` 는 하던 자리에서 멈춰 두었다가 `계속` 으로 이어서 합니다.
- `취소` 는 **기다리지 않고 바로** 작업을 놓고 창을 돌려줍니다. 반쪽짜리 파일이 남지 않고,
  그때까지 저장된 파일은 그대로 있습니다.

`진행 상황` 칸의 `기록 지우기` 를 누르면 그동안 쌓인 진행 내용을 비웁니다.
화면에만 있는 내용이라 저장된 파일이나 기록에는 영향이 없습니다.

한 번 저장한 스토리는 기록에 남아, 다음에 다시 나타나지 않습니다.

## 파일명 규칙 (exe)

```
YYMMDD @계정 #번호.확장자
```

- 번호는 **같은 날짜 + 같은 계정** 묶음 안에서 1부터 매깁니다.
- 그 묶음이 **한 개뿐이면 번호를 붙이지 않습니다.**
- 확장자는 사진이면 `.jpg`, 영상이면 `.mp4` 입니다.
- 날짜와 시각은 **로컬 시간** 기준입니다.
- 파일 수정시각을 스토리가 올라온 시각으로 맞춰 두어, 탐색기에서 시간순 정렬이 됩니다.

예를 들어 `@abc` 에서 8월 30일 2개 + 8월 31일 1개를 고르면:

```
260830 @abc #1.jpg
260830 @abc #2.mp4
260831 @abc.jpg
```

이미 같은 날짜·계정의 파일이 저장 폴더에 있으면 **그 뒤 번호부터 이어서** 매깁니다.
기존 파일을 덮어쓰거나 이름을 바꾸지 않습니다.

## 로그인에 대해 (exe)

**스토리는 로그인 없이는 가져올 수 없습니다.** 공개 계정이라도 그렇습니다.

대신 **매번 로그인하지 않아도 되게** 세 단계로 처리합니다.

1. `data/session.json` 에 저장된 세션이 있으면 그대로 사용 — 평소에는 여기서 통과합니다.
2. **세션이 만료됐으면 저장해 둔 아이디/비밀번호로 말없이 다시 로그인합니다.**
   창이 뜨지 않으므로 다시 입력할 일이 없습니다.
3. 저장된 정보가 없으면 브라우저(크롬·엣지 등)에 남아 있는 로그인 쿠키를 재사용합니다.
4. 그것도 안 되면 **로그인 창**이 떠서 아이디/비밀번호(필요하면 2단계 인증 코드)를 한 번만 받습니다.

### 비밀번호는 어떻게 보관하나요

instagrapi 는 세션 파일에 쿠키와 기기 정보만 저장하고 **비밀번호는 남기지 않습니다.**
그래서 세션이 만료돼도 다시 묻지 않으려면 비밀번호를 따로 보관하는 수밖에 없습니다.

윈도우 **DPAPI** 로 암호화해 `data/credential.bin` 에 둡니다.
**이 PC 에서 지금 로그인한 윈도우 계정으로만 복호화**되므로, 파일을 통째로 복사해
다른 PC 나 다른 계정으로 가져가도 읽지 못합니다. 파일 안에 평문은 들어 있지 않습니다.

지우고 싶으면 로그인 창의 **`저장된 로그인 정보 지우기`** 를 누르세요.
세션·비밀번호·기억한 아이디가 모두 지워집니다.

> **자동 로그인이 늘 되는 것은 아닙니다.** 2단계 인증이 켜져 있거나 인스타그램이
> 본인 확인(challenge)을 요구하면 코드 입력이 필요해 자동으로 끝낼 수 없습니다.
> 이때는 지금처럼 창이 뜹니다.

### 다른 계정으로 바꾸려면

**`로그인` 버튼**을 누르세요. 저장된 세션과 비밀번호를 무시하고 항상 로그인 창을 띄웁니다.
아이디는 지금 계정으로 미리 채워져 있으니, 바꿀 거면 지우고 새로 넣으면 됩니다.
성공하면 세션과 저장된 정보가 새 계정 것으로 바뀝니다.

지금 로그인된 계정은 창 오른쪽 위에 `@아이디` 로 표시됩니다.

### 이 PC에서 확인된 점

- **크롬·엣지 쿠키는 관리자 권한이 있어야 읽힙니다.** 크롬 127 버전부터 쿠키 암호화가
  강화되어(App-Bound Encryption), 일반 권한으로 실행하면 건너뜁니다.
- 파이어폭스는 이 PC에 설치돼 있지 않습니다.
- 관리자 권한이 번거롭다면 **3번(로그인 창에서 1회 로그인)이 더 편합니다.**

## "잠시 후 다시 시도해 주세요" 가 뜬다면

인스타그램이 요청을 일시적으로 막은 상태(레이트 리밋)입니다. **프로그램 문제가 아닙니다.**

- 짧은 간격으로 여러 번 실행하면 이 상태가 됩니다. **몇 분에서 몇 시간** 기다렸다 다시 시도하세요.
- 기다리는 동안 계속 눌러 보면 차단이 더 길어집니다. 이 프로그램은 레이트 리밋을 감지하면
  나머지 계정을 두드리지 않고 즉시 멈춥니다.
- 하루 몇 번 정도로 쓰는 것을 권합니다.

## 어떻게 가져오는지 (instagrapi)

스토리 수집에 **instagrapi** 를 씁니다. 실제 인스타그램 앱이 쓰는 비공개 모바일 API 를 통해
`feed/user/{id}/story/` 로 요청합니다.

예전에는 instaloader 를 썼는데, 이쪽은 웹 GraphQL 주소(하드코딩된 `query_hash`)로 스토리를
가져오는 방식이라 인스타그램이 이 경로를 막으면
`401 Unauthorized - "Please wait a few minutes before you try again"` 이 떠서 실패했습니다.

요청 사이에 1~3초 무작위 간격을 두어 차단을 피합니다.

# 웹으로 쓰기

브라우저를 화면으로 쓰는 방식입니다. **인스타그램 로그인이 필요 없습니다.**

```powershell
.venv\Scripts\python.exe -m storyge serve
```

브라우저가 저절로 열립니다 (`http://127.0.0.1:8760`). 멈추려면 콘솔에서 Ctrl+C.
`--port 9000` 으로 포트를 바꾸고, `--no-browser` 로 자동 열기를 끌 수 있습니다.

서버는 **이 PC 안에서만** 열립니다. 로그인이 없는 도구라서, 바깥에서 접속할 수 있게 열면
같은 망의 누구나 이 PC 저장 폴더에 파일을 쓰게 할 수 있습니다.

파일은 **브라우저가 아니라 서버(이 PC)의 저장 폴더**에 바로 저장됩니다.
exe 와 같은 폴더를 씁니다.

## 화면 쓰는 법

**계정 추가.** 왼쪽 위 칸에 계정을 적습니다. `abc`, `@abc`, 프로필 주소 아무 형태나 되고,
공백으로 구분해 여러 개를 한 번에 넣을 수 있습니다.

- **Enter** 를 누르면 목록에 넣기만 합니다.
- **Ctrl+Enter** 를 누르면 목록에 넣고 **방금 적은 계정만 바로 가져옵니다.**
- **`추가`** 버튼은 목록에 넣기만 합니다.
- 칸 옆의 **`⤢`** 를 누르면 넓은 입력 창이 열립니다. 긴 목록을 붙여 넣을 때 쓰세요.
  (창 안에서 Ctrl+Enter 가 `확인` 입니다.)

**계정 고르기.** 줄을 눌러 고르고, **끌어서 여러 줄을 한 번에** 고를 수 있습니다.
고른 계정이 있으면 `스토리 가져오기` 가 그 계정들만 봅니다. 하나도 없으면 전체를 봅니다.
두 개 이상 고르면 **`선택한 N개 삭제`** 버튼이 나타납니다. 한 개는 줄 오른쪽의 `✕` 로 지웁니다.

**목록 접기.** 목록 위 `Storyge` 오른쪽의 **`«`** 로 접고, 접힌 뒤에는 상단 왼쪽에 나타나는
**`☰`** 로 다시 폅니다. 접은 상태는 그 브라우저에 기억됩니다.

**너비 조절.** 왼쪽 목록과 오른쪽 사이의 경계선을 **끌어서** 비율을 바꿀 수 있습니다.
두 번 누르면 기본값으로 돌아갑니다. 바꾼 너비는 그 브라우저에 기억됩니다.

**저장 폴더.** 설정(⚙)의 **`폴더 선택`** 으로 탐색기 창을 띄워 고릅니다.
경로 칸은 읽기 전용이라 손으로 적을 수는 없습니다.
저장 폴더를 정하지 않은 채로 `스토리 가져오기` 를 누르면 곧바로 폴더 고르기로 이어집니다.

> 탐색기 창은 **서버를 띄운 PC 에** 뜹니다. 브라우저 창 뒤에 가려질 수 있으니
> 안 보이면 작업 표시줄을 확인하세요.

**새로고침.** 새로고침하면 돌고 있던 수집을 **멈추고** 처음 화면으로 돌아갑니다.
계정 목록과 설정은 그대로 남습니다.

## 스토리를 어디서 가져오나요

웹 버전은 두 가지 길을 순서대로 써 봅니다. 고를 것이 없으므로 화면에는 이 선택지가
나오지 않습니다.

1. **exe 로 로그인해 둔 세션이 있으면 그걸 씁니다.** 이 길로 오면 **게시 시각이 정확**하고,
   팔로우 중인 **비공개 계정**도 가져옵니다. 웹이 로그인을 묻는 일은 없습니다 —
   로그인은 exe 에서 한 번 하는 것이고 웹은 그 결과만 빌려 씁니다.

   세션이 만료돼도 **저장해 둔 아이디/비밀번호로 알아서 다시 로그인합니다**
   (가져오는 도중에 만료돼도 마찬가지입니다). 다시 입력할 일은 없습니다.
   다만 2단계 인증이 걸려 있거나 비밀번호가 바뀌었으면 자동으로는 끝낼 수 없어서,
   아래 2번으로 내려갑니다 — 그때는 exe 에서 한 번 다시 로그인해 주세요.
2. 세션이 없으면 공개 스토리를 받아 주는 **바깥 사이트**로 내려갑니다
   (`saveinsta.to` → `fastdl.app` → `igram.world`). 이때는 아래 제약이 붙습니다.

> **공유하는 것은 로그인 정보뿐입니다.** exe 는 exe 옆의 `data` 를, 소스로 띄운 웹은
> 프로젝트 폴더의 `data` 를 씁니다. `serve` 는 로그인 정보(`session.json`,
> `credential.bin`)만 **`dist\data` 에서 빌려 오고**, 계정 목록·저장 폴더·저장 기록은
> 각자 자기 폴더 것을 씁니다. 그래서 두 프로그램에 서로 다른 계정 목록과 저장 폴더를
> 둘 수 있습니다.
>
> 띄울 때 두 폴더가 콘솔에 찍힙니다. `--data <경로>` 로 설정 폴더를,
> `--login-dir <경로>` 로 로그인 폴더를 바꿀 수 있습니다.

미디어 파일 자체는 그 사이트를 거치지 않고 **인스타그램 서버에서 바로** 받습니다.
남의 무료 서비스에 영상 트래픽을 떠넘기지 않기 위해서입니다.

**바깥 사이트로 내려갔을 때만** 붙는 제약이 세 가지 있습니다.

- **공개 계정만 됩니다.** 비공개 계정은 안내만 뜨고 넘어갑니다. 팔로우 중이어도 안 됩니다.
- **올라온 시각을 알 수 없습니다.** 사이트가 원본 게시 시각을 주지 않아서 받은 시각을
  대신 씁니다. 그런 항목에는 `~` 가 붙고, 파일명의 날짜도 '받은 날'이 됩니다.
  (세션이 있으면 이 줄은 해당되지 않습니다 — 시각이 정확합니다.)
- **사이트가 바뀌면 멈출 수 있습니다.** 공개된 사용 방법이 있는 게 아니라 화면을 읽는
  방식이라, 상대가 바뀌면 고쳐야 합니다.

> 스토리가 하나도 없는 계정은 그냥 넘어갑니다. (사이트가 이 경우에도 "비공개"라고
> 답하기 때문에 둘을 구분할 수 없어, 없는 것으로 봅니다.)

또 하나: 내 계정 정보는 아무 데도 보내지 않지만, **어떤 계정을 보는지는 그 사이트가 알게 됩니다.**

## 파일명 규칙 (웹)

기본값은 **원본 주소에 들어 있는 이름 그대로**입니다. 예: `481234567_1122334455_n.jpg`.
이미 고유한 이름이라 번호를 붙일 필요가 없습니다.

설정에서 `파일 이름을 직접 정하기` 를 켜면 아래 토큰을 조합해 쓸 수 있습니다.
칩을 누르면 커서 자리에 들어가고, 아래에 결과가 바로 보입니다.

| 토큰 | 결과 | 예 |
|---|---|---|
| `{orig}` | 원본 이름 | `481234567_1122334455_n` |
| `{date}` | YYMMDD | `260830` |
| `{yyyy}` `{yy}` `{mm}` `{dd}` | 년 / 년2 / 월 / 일 | `2026` `26` `08` `30` |
| `{time}` | HHMM | `2105` |
| `{HH}` `{MM}` `{SS}` | 시 / 분 / 초 | `21` `05` `44` |
| `{account}` `{@account}` | 계정 | `abc` `@abc` |
| `{n}` `{nn}` | 번호 / 두 자리 번호 | `3` `03` |
| `{type}` | 종류 | `video` `photo` |

대소문자를 구분합니다 — `{mm}` 는 월, `{MM}` 는 분입니다.

대괄호로 감싼 부분은 **하나뿐일 때 통째로 빠집니다.** `{date} @{account}[ #{n}]` 으로 적으면
exe 와 똑같은 결과가 나옵니다.

확장자는 토큰이 없습니다. 받아 봐야 사진인지 영상인지 알 수 있어서 자동으로 붙습니다.
기존에 같은 이름의 파일이 있으면 exe 와 마찬가지로 **그 뒤 번호부터 이어서** 매깁니다.

## 웹에 없는 것

예약 수집, 보관함, 실행 기록, 로그인, 진행 기록 창, **즐겨찾기**는 웹에 **일부러 넣지
않았습니다.** 그 기능이 필요하면 exe 를 쓰세요.

즐겨찾기를 exe 에서 켜 두었다면 그대로 남습니다. 웹에서 계정을 넣거나 빼도 지워지지 않고,
웹 화면에 안 보일 뿐입니다.

## data 폴더

프로그램이 쓰는 파일은 전부 **exe 옆의 `data/` 폴더**에 저장됩니다.

| 파일 | 내용 |
|---|---|
| `config.json` | 저장 폴더 경로, 계정 목록, 즐겨찾기, 밝기(`theme`), 언어(`lang`), 삭제 전 확인(`confirm_delete`) |
| `session.json` | 인스타그램 로그인 세션 |
| `credential.bin` | 아이디·비밀번호 (윈도우 DPAPI 로 암호화, 이 PC·이 계정에서만 복호화) |
| `staging\` | 예약 수집이 모아 둔 스토리 (고르기 전 임시 보관) |
| `schedule.log` | 예약 실행 기록 (창이 없어 결과를 볼 방법이 이것뿐) |
| `run_state.json` | 지금·마지막 수집의 진행 상태 (예약 창에 보여 주는 값) |
| `downloaded.json` | 이미 저장한 스토리 기록 (중복 방지용) |
| `error.log` | 예상치 못한 오류가 났을 때만 생김 |

exe 를 다른 폴더로 옮길 때는 `data` 폴더도 함께 옮겨야 설정이 유지됩니다.

`config.json` 을 직접 고칠 일이 있으면 BOM 이 붙어도 읽히도록 해 두었습니다. 형식이 깨지면
`config.broken.json` 으로 치워 두고 빈 설정으로 시작하니 프로그램이 안 뜨는 일은 없습니다.

`data/session.json` 은 **로그인 세션 그 자체**라 유출되면 계정에 접근당할 수 있습니다.
`.gitignore` 에 `data/` 를 넣어 두었습니다. exe 를 다른 사람에게 줄 일이 있으면 `data` 폴더는 빼고 주세요.

## exe 다시 만들기

```
powershell -ExecutionPolicy Bypass -File build.ps1
```

`dist\Storyge.exe` 와 `dist\Storyge_demo.exe` 가 둘 다 새로 만들어집니다.

> **`build.ps1` 을 편집할 때 주의:** 이 파일은 **UTF-8(BOM 포함)** 으로 저장해야 합니다.
> Windows PowerShell 5.1 은 BOM 이 없으면 파일을 CP949 로 읽어서, 안에 든 한글이 깨지고
> 따옴표가 어긋나 `hash literal was incomplete` 같은 파서 오류로 실행이 아예 안 됩니다.
> 메모장에서는 "UTF-8 (BOM)" 으로, VS Code 에서는 우측 하단 인코딩을 "UTF-8 with BOM" 으로 저장하세요.

> **왜 `.venv` 를 쓰나:** instagrapi 는 `Pillow>=12.2` 를 요구하는데, 전역 파이썬에 설치된
> moviepy 는 `pillow<12` 를 요구해 서로 공존할 수 없습니다. 그래서 이 프로젝트만의 `.venv`
> 에서 빌드합니다. 전역 환경은 건드리지 않으므로 moviepy 를 쓰는 다른 작업은 그대로 됩니다.
> **`pip install instagrapi` 를 전역에 하지 마세요.** moviepy 가 깨집니다.

## 파이썬으로 실행하기

반드시 `.venv` 의 파이썬을 쓰세요.

```
.venv\Scripts\python.exe run.py          기본 화면
.venv\Scripts\python.exe run_insta.py    인스타 디자인
.venv\Scripts\python.exe -m igstory       기본 화면 (위와 같음)
```

웹 버전은 이렇게 띄웁니다. (패키지 이름은 `storyge` 입니다)

```
.venv\Scripts\python.exe -m storyge serve                  브라우저로 열기
.venv\Scripts\python.exe -m storyge serve --port 9000 --no-browser
```

인자를 주면 창 없이 콘솔에서도 쓸 수 있습니다. (exe 는 GUI 전용이라 인자를 받지 않습니다)

```
.venv\Scripts\python.exe -m igstory run --fav              즐겨찾기 계정만
.venv\Scripts\python.exe -m igstory run --accounts abc     특정 계정만
.venv\Scripts\python.exe -m igstory add abc def --fav      계정 추가 (여러 개)
.venv\Scripts\python.exe -m igstory rm abc def             계정 삭제 (여러 개)
.venv\Scripts\python.exe -m igstory ls                     등록 목록 (★ = 즐겨찾기)
.venv\Scripts\python.exe -m igstory fav abc / unfav abc    즐겨찾기 켜기/끄기
.venv\Scripts\python.exe -m igstory config --out "D:\스토리"  저장 폴더 지정
```

## 알아 둘 점

- 본인이 볼 수 있는 계정의 스토리를 개인적으로 보관하는 용도입니다. 비공개 계정은
  팔로우하고 있어야 가져올 수 있습니다.
- **스토리를 조회하면 상대방의 "조회자 목록"에 뜰 가능성이 큽니다.**
- 비공개 API 를 쓰는 방식은 인스타그램 이용약관에 어긋날 수 있고, 과하게 쓰면 계정이
  제한될 수 있습니다. 조금씩만 쓰세요.
- 백신 프로그램이 PyInstaller 로 만든 exe 를 오탐하는 경우가 있습니다. 차단되면 예외로 등록하거나,
  위처럼 파이썬으로 직접 실행하면 됩니다.
